# 04 SRS: FSRS

ส่วนที่สำคัญที่สุดของแอป ทุกข้อด้านล่างต้องมีทดสอบรองรับ

## ไลบรารี

ตัวเลือกที่ต้องประเมินตอนเริ่มสร้าง (ตรวจเวอร์ชัน, สัญญาอนุญาต, ความตรงกับต้นฉบับ)

| ไลบรารี | ลักษณะ |
|---|---|
| [`fsrs`](https://pub.dev/packages/fsrs) (pub.dev) | Dart ล้วน, พอร์ตจากทีม open-spaced-repetition |
| [`fsrs-rs-dart`](https://github.com/open-spaced-repetition/fsrs-rs-dart) | ผูก Rust (ตัวหลักที่ Anki ใช้) ผ่าน flutter_rust_bridge อาจมี optimizer |

**ยังไม่ยืนยัน:** optimizer (ปรับพารามิเตอร์) ใช้ได้บนมือถือหรือไม่ ถ้าไม่ได้ ทางสำรองคือส่งออก log ไปรัน optimizer ต้นฉบับบนคอม แล้วนำค่ากลับเข้าแอป

ห้ามเขียนสมการ FSRS เองจากความจำ ใช้ไลบรารีเท่านั้น และทดสอบกับ test vectors ของต้นฉบับ

## Wrapper ของเรา

```dart
abstract class Scheduler {
  CardState next(CardState state, Rating rating, DateTime now);
  double retrievability(CardState state, DateTime now);
  CardState replay(List<ReviewLogEntry> logs, FsrsParams params); // สร้างสถานะใหม่จาก log
}
```

- **ตัวจัดตาราง 2 ชุด:** `vocab` และ `grammar` แต่ละชุดมีพารามิเตอร์และ desired retention ของตัวเอง
- **Deterministic:** รับ `now` จากภายนอก ไม่เรียกนาฬิกาเอง, fuzz ใช้เมล็ดสุ่มจาก `hash(card_id, reps)` เล่น log ซ้ำได้ผลเดิมเสมอ
- บันทึก `params_version` และ `algo_version` ทุกครั้งที่ตอบ

## Grader: ให้คะแนนอัตโนมัติ (ไม่ประเมินตัวเอง)

| ผลลัพธ์ | Rating |
|---|---|
| ผิด / กด "ไม่รู้" / กด "เดา" (แม้ถูก) | Again (1) |
| ถูก แต่ใช้คำใบ้ หรือช้ากว่า 2.0× มัธยฐาน | Hard (2) |
| ถูก เวลาปกติ | Good (3) |
| ถูก เร็วกว่า 0.6× มัธยฐาน และไม่ใช้คำใบ้ | Easy (4) |

- มัธยฐานคิดแยกต่อ `question_type` จาก 200 ครั้งล่าสุด (ก่อนมีข้อมูลพอใช้ค่าเริ่มต้นใน config)
- เวลาตอบถูกตัดที่ 60 วินาที (กันวางเครื่องทิ้ง)
- **ลดการเดา:** ตัวเลือกใช้ตอนแนะนำคำใหม่และ learning steps เท่านั้น การทบทวนใช้การพิมพ์/เลือกจากตัวลวงที่ใกล้เคียง
- **ตัวลวง:** ชนิดคำเดียวกัน, ระดับใกล้กัน, ไม่ซ้ำความหมายกับคำตอบ
- **พิมพ์คำอ่าน:** รับทั้งคานะและโรมาจิ (แปลงเป็นคานะ), ยอมรับคำอ่านทุกแบบที่ JMdict ระบุ
- **พิมพ์ความหมายไทย:** ไม่ใช้ เพราะตรวจคำตอบภาษาไทยอย่างยุติธรรมยาก ใช้การเลือกแทน

## การจัดตาราง

| หัวข้อ | กติกา |
|---|---|
| วันเรียน | เปลี่ยนวันที่ 04:00 ตามเวลาท้องถิ่น เก็บ timezone ต่อการตอบ |
| Learning steps (คำใหม่) | 1 นาที → 10 นาที แล้วเข้า FSRS |
| Relearning steps | 10 นาที |
| Same-day review | ใช้ตามที่ไลบรารีรองรับ (FSRS-5+ มีสูตรเฉพาะ) |
| Fuzz | เฉพาะช่วง ≥ 3 วัน, deterministic |
| Maximum interval | 36,500 วัน (ค่ามาตรฐาน) ปรับได้ |
| การ์ดพี่น้อง | facet ของคำเดียวกันไม่ออกวันเดียวกัน (เลื่อนตัวที่ตามมาเป็นวันถัดไป) |
| ลำดับคำใหม่ | ตามระดับ (คานะ → N5 → … → N1) แล้วตาม `order_in_level` ผู้ใช้เลือกข้าม/เลือกระดับได้ |
| ลำดับการ์ดค้าง | R ต่ำสุดก่อน |
| คุมภาระ | ถ้าค้าง > `backlog_threshold` (ค่าเริ่ม 150) หยุดเพิ่มคำใหม่อัตโนมัติ แจ้งผู้ใช้ |
| กลับมาหลังหายไปนาน | ไม่รีเซ็ตอะไร FSRS คำนวณจากเวลาที่ผ่านไปจริง แนะนำเพดานทบทวนต่อวันชั่วคราว |
| Leech | lapses ≥ 8 → `is_leech` แสดงตัวอย่าง/หมายเหตุเพิ่ม และส่งเข้าคิวจุดอ่อนของโหมดฝึก ไม่ suspend อัตโนมัติ |

## การทบทวนนอกตาราง
โหมดฝึกและโหมดท้าทาย **ไม่ป้อน FSRS** เขียนลง `practice_log` เท่านั้น เพราะการทบทวนถี่ผิดธรรมชาติจะทำให้โมเดลประเมินความจำสูงเกินจริง

## Optimizer
- เปิดให้ใช้เมื่อมี review ≥ 1,000 ครั้งในโหมดนั้น
- แบ่งข้อมูล train/test ตามเวลา ยอมรับพารามิเตอร์ใหม่ **เมื่อ log-loss บนข้อมูลทดสอบดีกว่าค่าเดิม** เท่านั้น
- เก็บทุกเวอร์ชันใน `fsrs_params` ย้อนกลับได้, เปลี่ยนแล้ว replay log เพื่อคำนวณ due ใหม่
- แนะนำให้รันทุก ~1 เดือน

## การตรวจตัวเอง
- **กราฟ calibration:** แบ่ง `r_predicted` เป็นช่วง (เช่น 70–75%, …) เทียบกับอัตราถูกจริงของช่วงนั้น
- **Workload simulator:** เลื่อน desired retention / new per day แล้วเห็นภาระรายวันใน 30/90/365 วัน
- **ค่าแนะนำ desired retention:** แสดงตัวเลือกที่ให้ความรู้ที่จำได้ต่อเวลาเรียนคุ้มที่สุด (ถ้าไลบรารีรองรับการคำนวณนี้)

## ทดสอบ
1. Test vectors ของต้นฉบับ: ค่าที่ได้ตรงกัน
2. Replay: สถานะจาก replay เท่ากับสถานะที่เก็บไว้
3. Property tests: interval > 0, due เพิ่มขึ้นเมื่อ Good ติดต่อกัน, fuzz อยู่ในช่วง
4. จำลองผู้เรียนสมมติ 3 ปี (ความจำสุ่มตามโมเดล): ไม่มีกองค้างล้น, retention จริงใกล้ desired retention
5. ข้ามเขต timezone / เปลี่ยนเวลา / ตอบตอน 03:59 และ 04:01
